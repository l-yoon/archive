화면(UI)을 아무리 예쁘게 그려도, 개발에 들어가면 늘 같은 질문이 쏟아진다.  
**"로딩 중에 뒤로가기 누르면 어떻게 돼요?", "결제 실패하면 무슨 화면으로 가요?", "배송 시작된 후에도 주문 취소되나요?"**

화면만 보고 기획했기 때문에 생기는 구멍이다.  
**상태 다이어그램(State Diagram)**은 이 엣지 케이스를 단 한 장으로 정리해 개발자와 기획자 사이의 소통 비용을 90% 줄여주는 가장 강력한 도구다.

---

## 1. 상태 다이어그램이란?

어떤 대상(화면, 버튼, 주문 건, 유저)이 가질 수 있는 **모든 상태(State)**와, 그 상태가 **어떤 행동이나 사건(Trigger)으로 인해 다음 상태로 바뀌는지(Transition)**를 화살표로 나타낸 지도다.

### 핵심 3요소
1. **상태 (State)**: 대상이 머무르는 조건 (예: `결제 대기`, `배송 중`, `로그인 실패`)
2. **이벤트 (Trigger)**: 상태를 바꾸는 행동이나 사건 (예: `결제 승인 클릭`, `타임아웃 30초 초과`)
3. **전이 (Transition)**: A 상태에서 B 상태로 넘어가는 화살표

---

## 2. 실전 예시: 이커머스 주문 라이프사이클

글로벌 결제/주문 시스템이 굴러가는 핵심 로직:

```
[장바구니]
   │
   ▼ (주문서 작성)
[결제 대기] ──(카드 승인 실패)──► [결제 실패] ──(재시도)──┐
   │                                                     │
   │ (카드 승인 성공)                                      │
   ▼                                                     ▼
[주문 완료] ──(고객 즉시 취소)──► [취소/환불] ◄──────────┘
   │
   ▼ (배송 준비 및 송장 등록 — 이 시점부터 취소 불가)
[배송 중]
   │
   ▼ (수령 확인)
[배송 완료] ──(단순 변심/하자)──► [반품 신청] ➔ [반품 검수] ➔ [환불]
```

### 이 다이어그램 하나가 해결하는 것
- **"배송 중인데 취소 버튼 보여줘요?"** ➔ 다이어그램을 보면 `[배송 중]`에서 `[취소/환불]`로 가는 화살표가 없다. "취소 버튼은 숨기고, `[반품 신청]` 버튼만 띄운다"는 정책이 1초 만에 나온다.
- **"결제창 띄워놓고 10분 동안 결제 안 하면?"** ➔ `[결제 대기]`에서 `(타임아웃 10분)` ➔ `[주문 자동 취소]` 화살표를 그리면 끝난다.

## 3. UI/UX 디자이너가 반드시 그려야 할 4대 화면 상태

피그마에 데이터가 꽉 찬 '행복한 메인 화면(Happy Path)' 하나만 그려두면 실무에서 무조건 터진다.  
모든 컴포넌트와 화면은 아래 4가지 상태를 거친다:

| 상태 | 화면에 보여줘야 할 것 | 예시 트리거 |
| :--- | :--- | :--- |
| **1. 비어있음 (Empty)** | "아직 주문 내역이 없어요" 빈 상태 일러스트 + 바로가기 버튼 | 최초 가입 시, 검색 결과 0건 |
| **2. 로딩 중 (Loading)** | 스켈레톤 UI, 비활성화된 버튼 (중복 클릭 방지) | API 호출 시작 직후 |
| **3. 성공 (Success)** | 정상 데이터 목록 렌더링 | 데이터 패치 완료 (200 OK) |
| **4. 에러 (Error)** | "네트워크가 불안정해요" 안내 문구 + [다시 시도] 버튼 | 네트워크 끊김, 서버 500 |

```
[Empty] ──(데이터 생성)──► [Loading] ──(성공)──► [Success]
                              │
                              └──(실패)──► [Error] ──(재시도)──► [Loading]
```

---

## 4. 언제 그려야 하는가?

1. **조건에 따라 화면이 바뀌는 복잡한 폼(Form)을 기획할 때**  
   (예: 인증번호 3분 타이머, 5회 입력 실패 시 잠김)
2. **여러 명의 역할이 얽힌 권한 플로우를 짤 때**  
   (예: 기안 작성 ➔ 팀장 승인 대기 ➔ 반려 / 최종 승인)
3. **디자이너 ➔ 개발자 핸드오프 직전**  
   (피그마 화면 옆에 상태 다이어그램 1장만 붙여두면 개발 중 메신저 질문이 90% 사라진다.)

---

## 결론
화면(UI)부터 그리지 마라. **상태(State)부터 펜으로 그려라.**  
기획서 10장 쓰는 것보다, 대상의 시작점부터 끝점까지 화살표를 이어보는 10분이 모든 비즈니스 구멍을 막아준다.
