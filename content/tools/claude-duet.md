> [!NOTE] 패러다임의 전환
> 사용자가 질문을 입력해야만 입을 열던 **수동적 챗봇(Reactive AI)**의 시대는 끝났다.  
> **Claude Duet**은 사용자의 디바이스가 꺼져 있어도 클라우드에서 상시 대기하며, 먼저 상황을 감지하고 말을 걸어오는 **능동형(Proactive) 에이전트**다.

---

## 1. 챗봇과 듀엣(Duet)의 결정적 차이

기존 AI 도구(ChatGPT, 기본 Claude)는 빈 입력창에 사용자가 프롬프트를 쳐야만 동작했다. 하지만 사람이 가장 바쁠 때는 **"무엇을 물어봐야 할지 프롬프트를 작성할 시간조차 없다"**는 것이 본질적인 문제였다.

```
[기존 챗봇 (Reactive)]
사용자가 상황 인지 ──► 프롬프트 작성 ──► AI 대답 ──► 사용자가 직접 실행

[Claude Duet (Proactive)]
AI가 백그라운드 감지 ──► 선제적 브리핑 ──► 사용자 승인(1클릭) ──► AI가 대행 실행
```

---

## 2. 핵심 아키텍처 4가지

### 1) 모닝 브리프 (Morning Brief)
출근 전 이메일, 캘린더, 슬랙을 스스로 훑어보고 중요한 사항을 요약해 먼저 메시지를 보낸다.  
- *"오늘 오전 10시 미팅 관련해 클라이언트가 어젯밤 요청한 추가 자료 3건을 정리해 두었습니다. 전송 승인하시겠습니까?"*

### 2) 24/7 클라우드 가상 머신(VM) 상주
내 맥북이나 스마트폰이 꺼져 있어도 앤트로픽 서버의 독립 클라우드 인스턴스에서 계속 돌아간다. 약 3시간 주기로 연결된 업무 툴을 점검하며, 사용자의 개입이 꼭 필요한 타이밍에만 푸시 알림을 보낸다.

### 3) 안전장치 (Human-in-the-Loop Approvals)
AI가 스스로 행동하지만 위험한 경계(Trust Boundary)는 철저히 사람의 승인을 거친다.
- **승인 필수 작업**: 이메일 발송, 결제, 문서 삭제, 서명 등 (실행 계획을 카드 UI로 제시)
- **원천 차단 작업**: 금융 자산 이동, 주식 거래 등 민감 금융 거래는 승인 요청조차 불가하도록 하드코딩 차단

### 4) 마켓플레이스 6,000+ 커넥터 & 메모리 계승
기존 Claude 계정에 축적된 사용자 성향, 프로젝트 메모리, 커스텀 스킬(Skills)을 그대로 이어받는다. Gmail, Slack, Notion, Stripe, GitHub 등 업무 툴과 즉시 맞물린다.

## 3. 기획자 / 테크 빌더 관점의 UX 시사점

| 구분 | 1세대 AI (Chatbot) | 차세대 AI (Claude Duet) |
| :--- | :--- | :--- |
| **핵심 인터페이스** | 텍스트 입력창 (Chat Input) | 승인 및 알림 카드 (Approval Sheet) |
| **사용자 역할** | 질문자 및 실행자 | 감독관 (Reviewer / Approver) |
| **구동 트리거** | 사용자의 Enter 키 | 시간 경과, 외부 이벤트, 상태 변화 |
| **하드웨어 의존성** | 브라우저 탭 유지 필요 | 클라우드 백그라운드 자율 구동 |

- **입력 중심에서 결정 중심으로**: 제품 기획자는 이제 "어떻게 프롬프트를 잘 쓰게 유도할까"가 아니라, **"AI가 가져온 실행 계획을 사용자가 1초 만에 훑어보고 승인/반려할 수 있는 직관적인 UI"**를 설계해야 한다.
- **알림 피로도 제어**: 백그라운드 에이전트의 성공 여부는 '얼마나 자주 말하느냐'가 아니라 **'불필요한 알림을 얼마나 조용히 걸러내고 결정적 순간에만 나타나느냐'**에 달려 있다.

## 결론
Claude Duet은 "더 똑똑한 챗봇"이 아니라, **인간이 잊어버린 컨텍스트를 클라우드에서 대신 기억하고 먼저 챙겨주는 개인 비서 인프라**로의 진화다.
