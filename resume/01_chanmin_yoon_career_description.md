업무가 확장됨에 따라 PM 운영 자체를 자동화한 AI 에이전트 시스템을 직접 구축·운영하며, 비용 실측을 통해 불필요한 설계를 폐기하는 **‘언러닝(Unlearning)’**을 실천했습니다. 이제는 에이전시의 납품 단계를 넘어, 하나의 제품에 몰입해 사용자 반응과 데이터를 바탕으로 끝까지 제품을 성장시키는 프로덕트 조직에 기여하고자 합니다.

### [대표 프로젝트 1] 대형 어학교육 플랫폼 전면 리뉴얼 — QA 및 릴리즈 총괄
`2025.08 ~ 현재 (13개월)` · 고객: 국내 대형 어학교육 기업(상장사 계열) · 팀: 오프쇼어 9명 + PM 1 (단독)  
스택: NestJS / Next.js / Flutter / ASP.NET(레거시) / MSSQL / MySQL

> **핵심 역할**: 3개 레거시 시스템을 통합하는 신규 플랫폼 전환에서 기획 정합성 검증, QA 사이클, 고객사 커뮤니케이션 전반을 전담.

- **명세서 누락 서피스(19개 화면) 발견 및 신규 집필**
  - **[배경]** 기획 명세서와 실제 배포본 간의 정합성 검증 부재로 런칭 시 대규모 사용자 민원 우려.
  - **[과정]** 배포 번들에서 화면 라우트를 전수 추출(관리자 107개, 앱 33개, 홈페이지 19개)하여 명세서와 기계적으로 대조.
  - **[결과]** 학생·학부모용 홈페이지가 명세서에서 통째로 누락된 것을 발견해 신규 챕터로 집필, 라우트 118개 + API 61개 대조 누락 0건 확정.
- **변경요청 60건 전수 분석 및 68% 범위 외 입증**
  - **[배경]** 고객사는 "요구가 반영되지 않는다", 개발팀은 "요구가 계속 늘어난다"며 감정적 대립 지속.
  - **[과정]** 60건의 변경요청을 3개 근본원인(A. 스펙 오해 16건 / B. 계약 외 신규 요구 41건 / C. 스펙 모호 3건)으로 전수 분류. 우리 쪽 오해 16건을 먼저 인정하고 41건의 신규 요구를 데이터로 제시.
  - **[결과]** 68%가 계약 범위 밖임을 입증하여 불필요한 감정 소모를 종식하고, 추가 개발 일정 및 계약 재협상의 정량 근거 확보.
- **레거시 데이터 45.5만 건 무손실 이관 조율**
  - **[과정]** 2개 레거시 DB의 소스 인수 범위, DB 권한, 미이관 자산(이미지 616건, 첨부 457건)을 목록화하여 사전 리스크 가시화.
  - **[결과]** 총 455,447건 중 454,917건 성공 (99.88% 무손실 이관 달성).
- **역할별 권한 매트릭스 전수 검증 및 일일 결함 추적**
  - 64개 화면 × 5개 역할 계정(최고관리자, 지사장, 분원장, 강사, 학부모)을 직접 로그인 실측하여 권한 표기 오류 및 화면 미노출 결함 선제 차단.
  - 항목번호 기반의 일일 결함 트래커를 운영하며 개발팀 작성 문서를 검토·승인 후 고객사에 발송, 142건 중 101건(71.1%) 결함 완결 추적.

  - 산출물마다 독립 검증자를 별도 기동하여, 작성자가 쓰지 않은 경로로 재측정하는 품질 게이트 수립. (운영 규칙 40여 개, 재사용 스킬 21개 자산화)

  - **[가설]** 일이 들어왔을 때 즉시 반응하도록 7개 에이전트 레인을 상시 대기시키는 구조 구축.
  - **[측정]** 실제 비용을 분석한 결과, 레인들이 하루 약 670회 기상하는 동안 24시간 내 실제 처리 일감은 2건에 불과함을 확인. "조용한 상태"를 유지하고 확인하는 데 막대한 비용이 소모되고 있었음.
  - **[판단 및 조치]** 본인이 설계한 방식의 비효율을 인정하고, 상시 대기 편성을 즉시 폐기하여 '호출 시 기동(On-Demand)' 방식으로 전면 재설계.
  - **[인사이트]** *"조용한 것은 싸다는 증거가 아니다"*라는 업무 원칙을 도출하고 시스템에 반영.
